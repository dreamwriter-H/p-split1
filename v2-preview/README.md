# Split Easy v2.2.0 Preview — 中文輸入、索引與登入穩定版

本版本直接延續 v2.1.0 的聚餐、旅遊、收據、Google 登入與即時共編功能；不是從零重做 App，也沒有覆蓋任何舊版本。

- 固定正式入口（目前仍是 v2.1）：<https://dreamwriter-h.github.io/p-split1/>
- v2.2 驗收入口：<https://dreamwriter-h.github.io/p-split1/v2-preview/>
- 本機版本目錄：`versions/v2.2.0-ime-index-recovery/`
- 預覽程式 commit：`待部署後填入`
- 正式發布 commit：`尚未發布`

> v2.2 預覽使用獨立的 `spliteasy-v2-2-preview` 資料空間與個人索引。驗收期間不讀寫正式 v2.1 帳本；正式入口與正式資料尚未切換。

## v2.2.0 Preview 本次完成

- 修正 Safari／iPhone 中文輸入法：所有名稱欄位在事件 handler 內立即擷取字串，不再把可能失效的 React event 留到 state updater 才讀取。
- 涵蓋聚餐名稱、旅遊名稱、聚餐與旅遊成員、餐點／支出名稱及收據校對文字。
- 新增 React ErrorBoundary；若仍遇到執行錯誤，會顯示可重新載入的復原畫面，而不是整頁白畫面。
- 畫面顯示 `APP_VERSION` 與 build id，方便確認手機是否仍載入舊快取。
- Firebase Auth 會先完成 `browserLocalPersistence` 設定，才啟動登入狀態 listener。
- 登入後顯示 Google email 與 UID 尾碼；若 Safari 私密模式或 App 內建瀏覽器無法保存登入，會清楚提示。
- 首頁索引遇到單次 `permission-denied`、離線或 pending writes 時不再自動刪除，改為保留索引、安全重試並顯示「權限待確認」。
- 建立、加入及成功開啟專案後都會執行 `ensureIndex`；有效成員重新由邀請連結進入時可自動補回缺漏索引。
- 移除共編者、協作者自行離開及擁有者刪除專案時，成員文件與對應 v2.2 預覽索引會在同一批 Firestore 操作處理。
- 只清理 Split Easy 明確命名的舊 localStorage keys，不會清除瀏覽器其他網站資料。
- 已建立唯讀 `v2.2-data-dry-run.cjs` 與 `DATA_RESET_GATE.md`；目前沒有執行任何資料刪除。

## 發布閘門

1. 先通過 Babel、靜態驗證、Firestore Rules dry-run 與 `/v2-preview/` 實機測試。
2. 回報使用者並等待明確驗收。
3. 驗收後才重新盤點正式 v2.1 資料，取得「永久且不可復原」的刪除確認。
4. 保留 Google Auth 使用者與 GitHub 歷史，再執行正式資料重置與 root 切換。

## v2.1.0 既有功能

### v2.1.0 完成內容

- 旅遊模式的「拍收據自動填寫」已正式完成，不再顯示「努力更新中」。
- 拍收據時可選「臺灣電子發票」或「海外一般收據」。
- 臺灣模式沿用雙 QR 本機解析；海外模式使用瀏覽器端 Tesseract.js OCR，支援英文、日文、韓文與繁體中文，不需要 Gemini、Ultra 訂閱或個人 API Key。
- 海外收據會嘗試帶入店名、日期、幣別與總額；辨識信心不足或幣別不明時會要求人工核對，不會直接寫入錯誤資料。
- 外幣支出保留原幣、原始金額與人工輸入的換算匯率，旅遊結算仍統一使用新臺幣，避免混合幣別直接相加。
- 收據確認後會回到既有支出視窗，再選擇旅遊天數、付款人與分攤成員；原本的共同錢包與多人代墊功能完整保留。
- 新增獨立「共編管理」頁面：擁有者可查看成員、建立新邀請、撤銷未使用的邀請連結，以及移除既有協作者。
- 撤銷邀請不影響已加入的成員；移除成員則會立即取消該帳號的專案讀寫權限。
- Firestore 規則不再因殘留首頁索引而放行專案讀取；失效索引會由被移除者自己的 App 自動清理。
- 收據照片只存在目前瀏覽器記憶體，不上傳 Firebase；Firebase 只保存經使用者確認後的必要記帳欄位。

## v2.0.2 既有穩定修正

- 中文輸入期間暫停接收雲端畫面覆寫，也暫停把尚未選字完成的注音送上雲端；選字完成後才同步完整文字。
- 修正 Safari 輸入聚餐名稱、旅遊名稱、成員名稱及餐點名稱時，可能只留下第一個注音符號的問題。
- 專案更新由「整份文件覆蓋」改為「只記錄本次變動的欄位」，不同裝置同時修改不同成員或不同品項時可各自保留。
- 寫入 Firestore 前使用交易重新讀取最新版資料，再套用本機變動，避免較慢送出的舊畫面把較新的共編內容蓋回預設值。
- 本機合併測試已涵蓋不同成員、不同專案欄位、不同金額、品項新增／刪除等七種衝突情境；仍須以兩支實機做最後驗收。
- 若兩人同時修改「同一個欄位」，仍以最後成功寫入的內容為準，這是目前版本刻意採用的規則。

## v2 核心架構

- 取消匿名登入，使用 Google 帳號作為跨瀏覽器、跨手機都一致的身分。
- 首頁不再把 `localStorage` 當成正式專案目錄，改讀 `users/{uid}/projects` 的雲端成員索引。
- 首頁只列出「我建立的」與「朋友分享」的專案，並清楚顯示角色。
- 同一個專案只有一份正式資料；不同使用者或裝置加入共編時，不會再複製另一個房間。
- 只有專案擁有者能建立邀請連結或永久刪除專案；協作者可離開專案，但不能刪除大家的資料。
- 邀請建立後會顯示完整網址，並提供「複製連結」及手機「系統分享」；自動複製失敗時仍可長按網址。
- GitHub Pages 上的 Google 登入改用 `signInWithPopup()`，避免整頁重新導向因跨網域儲存限制而返回登入頁形成循環。
- 彈出視窗若被 App 內建瀏覽器阻擋或逾時，會停止載入狀態並明確提示改用外部 Chrome／Safari。
- 每台裝置第一次開啟 v2 時，會刪除 v1 的本機首頁清單與殘留匿名登入。
- v1 舊邀請連結與舊資料路徑停用，避免清除後被舊分頁重新寫回。

## v2 資料結構

```text
apps/spliteasy-v2/projects/{projectId}
  members/{googleUid}
  invites/{randomInviteId}

users/{googleUid}/projects/{projectId}
```

- `projects` 是唯一正式專案資料。
- `members` 是專案權限名單。
- `invites` 是高強度隨機邀請碼；不能列出，只能讀取網址指定的單筆。
- `users/{uid}/projects` 是個人首頁索引，不保存另一份帳目。

## 完整保留的功能

### 聚餐模式

- 均攤、各自套餐與共享／指定／個人品項混合分攤。
- 每筆品項的「全員」按鈕可反覆切換全選／全不選。
- 百分比或固定服務費、墊付人、整數尾差與結算轉帳。
- 臺灣電子發票整張拍攝、雙 QR 本機辨識及匯入前校對。

### 旅遊模式

- 共同錢包、多人代墊與複雜分攤。
- 第 1 天、第 2 天等日程分頁，可隨時回頭新增或編輯先前天數。
- 每日小計與整趟旅程結算。
- 臺灣電子發票雙 QR 及海外一般收據本機 OCR 匯入。
- 外幣原始金額、幣別、人工匯率與新臺幣換算紀錄。

## Firebase 上線必要設定

1. Authentication 啟用 Google 登入，並停用 Anonymous。
2. Authorized domains 加入 `dreamwriter-h.github.io`。
3. 部署本版本的 `firestore.rules`。
4. 驗證 Google 登入、建立專案、邀請加入、跨裝置首頁與權限拒絕。
5. 確認 v2 正常後，才清除 v1 舊路徑資料與舊匿名 Auth 使用者。

詳細切換順序見 `MIGRATION_CHECKLIST.md`。

## 隱私與費用

- Google 登入只用來辨認使用者與專案權限，App 不會取得 Google 密碼。
- 發票與海外收據照片都只在裝置瀏覽器內解析，不上傳 Firebase；OCR 字庫由 CDN 在使用時下載。
- 小型親友使用通常可落在 Firebase 免費額度內；仍應在 Firebase Console 設定用量警示並定期查看讀寫量。
